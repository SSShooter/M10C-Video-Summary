## 修 Siri Glow 光雾的翻车

用户截图反馈：思维导图面板「Connecting...」时出现一大块淡紫粉**矩形色块**，遮住内容区。

根因：我为了适配更高的面板，把 demo 的「超大圆 + overflow 裁剪」改成了「元素 inset:0 铺满容器再缩放」。
元素边界因此变成可见的矩形；且面板是 400×640 竖长比例，铺满式光雾糊掉整块内容区。

修法（已确认后实施）：
- 光雾退回 demo 几何：`top:0; left:50%; translate(-50%,-50%)` 的圆，`--m10c-wave-size: min(170%, 460px)`，
  直径随宽度走但封顶，面板再高也只漫在顶部一片。
- 加 `mask-image: radial-gradient(circle closest-side, #000 55%, transparent)`，边缘再化开一层。
- 强度压一档：色团 alpha 0.55/0.5 → 0.42/0.4，关键帧 opacity 0.6/0.55/0.45 → 0.5/0.45/0.36，blur 56px。

教训：demo 里「看不到边界」是效果的成立条件，不是可以省掉的细节。改几何前先想清楚哪条约束在撑观感。

截图核验方式：临时 HTML 链接源 `assets/style.css`，用 headless Chrome + 负 `animation-delay` + `paused`
把动画钉在 30% / 70% / 点亮 / 流式四个状态。注意源 CSS 里没有 tailwind 产物，harness 要自己补 `flex-1` / `min-h-0`。

## 思维导图暗色可读性（仅诊断，未改代码）

两个面板外壳都写死 `bg-white`（`SubtitlePanel` L331、`article-mindmap.content` L81），
但 MindElixir 主题跟的是**操作系统**：

- 构造函数内部：`this.theme = theme || (prefers-color-scheme: dark ? DARK_THEME : THEME)`
  —— 所以只在外部调 `changeTheme` 不够，必须 `new MindElixir({ theme })` 显式传。
- `MindElixirReact` L48-56 又额外监听了一遍 `prefers-color-scheme`。

实测 DARK_THEME 的文字对比度是**达标**的（不算"看不清"的根因）：
`#cccccc` on `#252526` ≈ 9.5:1；白字 on `#4c4f69` ≈ 8:1；白字 on `#2d3748` ≈ 12:1。
真正割裂的是：白面板里嵌 `#252526` 画布 + 边框 `hsl(var(--border))` 是浅灰、深底上几乎消失 + 光环的 blur 在深底上发浑。

## 只修光环在深色画布上的表现（已实施）

用户明确只处理"光环在深色底上效果不佳"。做法是给光环加一套深色变体，而不是改主题体系：

- `MindElixirReact` 新增 `onThemeChange` 回调 + 导出 `getMindmapThemeType()`，回报实例**实际**用的主题
  （用 ref 转存回调，避免调用方传内联函数把实例重建掉）。
- `MindmapDisplay` 用 `canvasTone` 状态接住，传给 `GenerationGlow` 的新 prop `tone`。
  注意传的是 `mindmapData ? canvasTone : "light"`——画布没渲染前底是白框，按深色调会过曝、
  也会把 `ReasoningDisplay` 的 `text-gray-600` 埋掉。
- CSS `.m10c-is-dark` 变体：环加宽 2→4px、模糊 8→6px、`saturate(2)`、`brightness(boost*1.5)`，
  并加 `mix-blend-mode: plus-lighter`（加色混合）。

关键认知：白底靠"模糊柔光"就够，因为浅背景会把微弱的色差放大；深底必须靠**光通量**——
模糊会把 2px 线的能量摊薄 8 倍，深底上直接消失。所以深色变体是"更宽的环 + 更小的模糊 + 加色"。
